# Сохранение между устройствами

Проверка 24 сентября 2026: до этого изменения сервер сохранял профили по случайному браузерному токену. Сам по себе вход в VK не связывал два устройства. Имя игрока и ответ VKWebAppGetUserInfo не являются доказательством владения аккаунтом.

Добавлен POST /api/auth/vk. Worker проверяет HMAC-SHA256 параметров запуска, идентификатор приложения 54626490, VK ID и vk_ts (не старше суток). Проверка основана на официальном примере: https://github.com/VKCOM/vk-apps-launch-params/blob/master/examples/python3.py. Дубликаты параметров и чужие подписи отклоняются. Секрет хранится только в Worker, не в клиенте.

Первый подтверждённый вход привязывает текущий гостевой профиль. Если профиль этого VK ID уже существует, второе устройство получает именно его, без суммирования валют и XP. Другой аккаунт VK не наследует уже привязанный профиль. Предыдущий браузерный токен при переключении сохраняется локально отдельно. Конкурирующие первые входы используют атомарную проверку revision D1.

## Что требуется для включения

В рабочем Worker **obiteldead** установить секрет **VK_APP_SECRET** со значением актуального защищённого ключа приложения 54626490. Не добавлять ключ в GitHub, клиентские файлы или публичные vars. Настройка выполнена; подтверждение и ограничения проверки описаны ниже.

Поддержан запуск Mini Apps с подписанными vk_* параметрами и sign в URL. Старый запуск VK Games через viewer_id/auth_key этим обработчиком не подтверждается; запуск без sign остаётся гостевым. Также гостевым остаётся открытие GitHub Pages вне VK. После настройки требуется реальный вход с одного VK аккаунта на ПК и телефоне и сравнение прогресса.

При отсутствующем секрете или ещё старом сервере клиент явно показывает «ГОСТЕВОЙ ПРОФИЛЬ». При поддельной/устаревшей подписи подключение отклоняется. В настройках объясняется статус сохранения.

## Проверки

Автотесты проверяют два независимых браузерных токена с одним подписанным VK ID: одинаковые XP, валюта, автомобиль и имя. Проверены другой VK ID, поддельная подпись, чужое приложение, истёкший запуск, повтор параметра, отсутствие секрета и одновременная первая привязка. Это тесты Worker с SQLite-адаптером, не подтверждение настройки живого VK/Cloudflare.

По явному разрешению владельца защищённый ключ приложения сохранён через Cloudflare Dashboard как Production runtime Secret `VK_APP_SECRET` у Worker `obiteldead`, выполнено Add variable and deploy. В таблице подтверждено Value encrypted. Значение не записывалось в репозиторий. Запрос POST /api/auth/vk с пустыми параметрами вернул 401 вместо 503; это подтверждает наличие серверной настройки и отказ неподтверждённому входу, но не заменяет проверку настоящих параметров запуска VK и двух устройств.
